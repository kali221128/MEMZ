## 1. 概述

**MEMZ**（俗称"彩虹猫病毒"，英文常称 *MEMZ Trojan* / *MEMZ Joke Malware*）是 2016 年公开传播的 Windows 平台恶意程序。其核心特征为**大量恶搞型 Payload + 覆盖主引导记录（MBR）**，在娱乐化外观之下具备**不可逆的系统破坏能力**。

按传播方式划分，MEMZ **不具备自我复制与网络传播能力**，需用户主动执行，因此在分类上更接近 **Trojan / Joke Malware（木马 / 玩笑类恶意软件）**，而非严格意义上的"病毒"。但其 MBR 写入行为使其实际危害远超普通恶作剧程序。

| 属性 | 说明 |
|---|---|
| 常见名称 | MEMZ、彩虹猫病毒、Nyan Cat Virus |
| 分类 | Trojan / Joke Malware / Bootkit（附带引导级载荷） |
| 目标平台 | Windows（x86 / x64） |
| 传播方式 | 无自动传播，依赖用户手动执行 |
| 持久化 | 写入 MBR 的引导级 Payload |
| 主要危害 | MBR 覆盖、数据破坏（破坏版）、系统无法启动 |
| 网络行为 | 基本无（无 C2、无回连） |
| 首次公开 | 2016 年 |

> **分类学说明：** 严格意义上 MEMZ **不是"病毒"**——它无自我复制机制、无文件感染/寄生行为、无网络或介质传播能力。更准确的定位是**携带引导区破坏载荷的木马/玩笑程序**。"病毒"为网络俗称。

## 3. 历史背景

MEMZ 由作者 Leurak 制作，并投稿给知名恶意软件分析类内容创作者 **danooct1** 的 *Viewer-Made Malware*（观众投稿恶意软件）系列。该系列本身以**分析、演示、教育**为目的，并在隔离环境中运行样本，MEMZ 因此获得大量曝光。

其标志性的"彩虹猫（Nyan Cat）动画引导画面"——在 MBR 被覆盖、系统重启后由自写引导代码直接在屏幕上渲染——使其成为互联网上辨识度最高的恶意软件之一，也常被用于网络安全入门科普中说明**"引导区破坏"**的概念。

> **重要提示：** 作者公开作品的语境是演示与教育，**不代表该样本可以安全运行**。原版即会造成 MBR 被覆盖，破坏版会造成数据不可恢复的损毁。

## 4. 版本与变体

据公开资料，作者发布过多个版本，行为差异显著：

| 版本 | 主要差异 |
|---|---|
| **MEMZ**（原版） | 完整恶搞 Payload 序列 + 末尾覆盖 MBR；重启后进入彩虹猫引导画面，系统无法正常启动 |
| **MEMZ-Destructive** | 破坏性进一步加强，会对磁盘文件进行覆盖/损毁，数据恢复难度极高 |
| **MEMZ-Clean** | 仅保留彩虹猫相关的视觉/声音 Payload，**不写入 MBR**，破坏性大幅降低，通常用于演示 |
| **MEMZ-Trojan** | 原版体系的变体版本，公开技术细节相对较少，建议以原始发布页与专业分析报告为准 |

> **⚠️ 第三方改包风险：** 网络上存在大量**二次打包、改名、加壳**的第三方版本，行为可能与上述描述不符，甚至叠加了真实的信息窃取木马。任何来源不明的"彩虹猫"程序都应视为高危样本。

## 5. 技术分析

### 5.1 整体执行流程
用户执行 MEMZ.exe
│
├─► 检查 / 提升权限（写入物理磁盘需管理员）
│
├─► 启动多个并发线程，依次触发视觉 / 听觉 / 交互类 Payload
│
├─► 结束阶段：弹出提示（原版会告知即将发生的后果）
│
└─► 打开 \.\PhysicalDrive0，写入自制 512 字节引导扇区
│
└─► 用户重启 → BIOS 加载被覆盖的 MBR → 彩虹猫引导画面

text

### 5.2 关键技术点

#### a) MBR 覆盖（核心破坏行为）

Windows 允许具备管理员权限的进程以**原始设备**方式打开物理磁盘（如 `\\.\PhysicalDrive0`），并直接写入扇区。MEMZ 正是利用这一机制，将前 **512 字节（主引导记录）** 替换为自制的引导代码。

- 该行为**绕过文件系统层**，常规杀毒软件的"文件扫描"逻辑难以在事后修复
- 一旦重启即生效
- 属于经典 **bootkit** 手法

#### b) 自制引导代码（Bootloader Payload）

被写入的引导代码在**实模式**下运行，直接通过 BIOS 显示中断绘制图形（彩虹猫动画），而非加载任何操作系统。

- 画面**不依赖 Windows 或任何已安装软件**
- 这是此类 bootkit 类 Payload 的典型表现
- 引导流程走完后，依据版本不同，系统会卡死、报错或进一步破坏数据

#### c) 用户态干扰 Payload

采用**多线程并行触发**，常见干扰手段包括：

| 类别 | 行为 |
|---|---|
| 输入劫持 | 光标被替换、反转或跳变，鼠标不受控 |
| 屏幕抖动 | 窗口位置被高频随机修改，制造"震动"效果 |
| 窗口洪泛 | 批量启动系统程序或弹窗，耗尽桌面资源 |
| 文本注入 | 向记事本等程序写入随机内容 |
| 声音播放 | 循环播放音效 |
| 视觉错乱 | 屏幕内容显示异常、颜色/字符混乱 |

#### d) 单文件、无外联

样本为单个 PE 文件，不释放大量附属组件、不依赖网络下载：

- 易于打包分发
- 沙箱中的网络监控难以触发告警
- **⚠️ 重要教训：网络层无异常并不代表样本无害**

> 以下为公开分析中常见的 Payload 类别描述，具体顺序与触发时机**因版本而异**，不做逐条精确复现。

| 阶段 | 典型行为 | 用户可感知表现 |

| 早期 | 光标劫持 | 鼠标不受控、指针变形 |

| 重启后 | **引导级彩虹猫** | 开机即进入动画，无法进入系统 |

## 8. 感染迹象与 IoC

### 8.1 执行阶段（未重启前）

- 出现无法解释的鼠标异常、屏幕抖动、大量弹窗
- 系统盘出现异常写入活动，尤其是**对物理磁盘的原始写入**
- 来源不明的单个小型 `.exe` 出现在下载目录、桌面、启动项
- 安全软件报告"引导区 / 物理磁盘写入"类告警

### 8.2 重启后

- 开机不进入 Windows，直接出现彩虹猫动画或黑屏 / 报错
- 出现 `Operating System not found`、`Bootmgr is missing` 等引导错误
- 使用 PE 启动盘检查，发现磁盘前 512 字节内容异常（非标准引导代码）

### 8.3 检测思路

| 检测层 | 建议 |
|---|---|
| 行为检测 | 监控对 `\\.\PhysicalDrive*` 的原始写入（**核心锚点**） |
| 引导完整性 | 校验 MBR/VBR、启用 Secure Boot 日志审计 |
| 文件检测 | 仅作辅助，因哈希不稳定 |
| 网络检测 | 基本无效（样本无外联） |

## 9. 影响与恢复

| 场景 | 影响 | 恢复路径 |
|---|---|---|
| 仅运行 Clean 版 | 桌面干扰，无持久破坏 | 重启或结束进程即可 |
| 原版（已写 MBR，未重启） | 系统仍可用，但已埋雷 | **立即关机，不要正常重启**；用 PE 盘重建引导 |
| 原版（已重启） | 无法进入系统 | 用安装介质进入修复环境，执行引导修复 / 重建 MBR |
| Destructive 版 | 文件被覆盖，数据损毁 | 引导可修复，但**被覆盖的数据通常不可恢复** |

### 9.1 恢复步骤（防御性操作）

1. **第一时间断电**，避免引导代码再次执行或造成更多写入
2. 使用**另一台设备**制作 Windows 安装 U 盘或 PE 维护盘
3. 在恢复环境中重建引导记录与分区表信息
4. 若为破坏版，优先**镜像整个磁盘**再做数据恢复尝试，避免二次损伤
5. 若涉及重要数据，交由专业数据恢复机构处理

> **引导修复参考（Windows 恢复环境）：**
> ```cmd
> bootrec /fixmbr
> bootrec /fixboot
> bootrec /rebuildbcd
> ```
> 上述命令为**防御性修复操作**，仅在合法的系统恢复场景下使用。若分区表受损，可能还需配合 `diskpart` / 专业分区工具。

## 10. 检测与防护建议

### 10.1 终端与策略层面

- 启用基于**行为**的 EDR 规则：监控对物理磁盘的原始写入、MBR/VBR 修改
- 开启**受控文件夹访问**、应用白名单，限制未知可执行文件运行
- 普通用户账户**不使用管理员权限**日常操作
- 开启 **Secure Boot 与 UEFI 启动**（可显著提高此类传统 MBR bootkit 的生效门槛）
- 定期备份：采用 **3-2-1 备份策略**，并确保备份离线 / 不可写

### 10.2 人员与流程层面

- 向用户普及"**网盘分享的可执行文件 = 高危**"的认知
- 明确禁止在办公设备上运行"挑战类"程序
- 建立样本上报与隔离流程

### 10.3 分析层面

- 仅在**一次性虚拟机 + 快照**中运行
- 不挂载共享文件夹、不启用剪贴板共享、不启用拖拽
- 样本执行前先做静态检查（PE 结构、导入表、字符串）
- 全程录屏 + 行为日志采集，便于事后复盘

## 12. 常见误区

> 本节汇总围绕 MEMZ 的高频错误认知。误区之所以危险，在于它们会直接导致**错误的处置决策**（例如"重启看看"或"虚拟机里随便跑"），从而放大实际损失。

### 12.1 认知误区对照表

| # | 常见误解 | 事实 | 误解根源 | 错误决策的后果 |
|---|---|---|---|---|
| 1 | "它不联网，所以无害" | 破坏完全在本地完成，MBR 写入**不需要任何网络** | 以"是否有 C2/外联"作为唯一危害判据 | 放行样本，错过唯一的阻断窗口 |
| 2 | "重启一下就好了" | **重启恰恰是触发引导级 Payload 的条件** | 把用户态干扰误判为全部行为 | 主动触发不可逆的引导破坏 |
| 3 | "在虚拟机里跑就一定安全" | 虚拟机可隔离 MBR 破坏，但**共享文件夹 / 剪贴板 / 拖拽**可造成宿主侧风险 | 混淆"计算隔离"与"数据通道隔离" | 宿主机文件被污染、样本外泄 |
| 4 | "它是病毒" | 无自我复制、无文件感染、无传播能力；分类为**木马 / 玩笑程序** | 网络俗称的泛化使用 | 按"病毒"设计防护策略，忽略引导区维度 |
| 5 | "Clean 版无害，可以随便跑" | 仍属未授权软件；**第三方改包**可能已注入真实恶意代码 | 以官方版本行为推断所有同名文件 | 运行来源不明程序，引入真实窃密木马 |
| 6 | "杀毒软件能直接修好" | MBR 层破坏通常需**离线修复**，在线查杀无法回写引导区 | 高估 AV 的修复能力边界 | 反复重启，扩大破坏面 |
| 7 | "有哈希就能识别" | 二次打包 / 加壳使哈希**极不稳定** | 以文件特征替代行为特征 | 检测被轻易绕过 |
| 8 | "看视频里没事，所以我也试试" | 演示视频在**隔离环境**中录制，且往往使用 Clean 版或已做剪裁 | 忽略演示语境与安全前置条件 | 在真实设备上造成不可逆损毁 |

### 12.2 三条核心结论

1. **危害判据应基于"行为"而非"外联"。** 无网络行为的样本同样可以是高破坏性样本。
2. **重启不是修复手段，而是触发器。** 怀疑 MBR 被写入时，正确动作是**断电 + 离线修复**。
3. **隔离是分层的。** 计算隔离（虚拟机）≠ 数据隔离（共享通道）≠ 网络隔离（Host-Only）。三者需同时满足。
